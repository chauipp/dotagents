## Agent

Tôi đã xem trực tiếp G:\dotagents. Kết luận: hiện tại repo chưa hoàn thành đúng kiểu bạn mong muốn.

Repo này hiện là một bộ rules + skills + installer, không phải một chat runtime có parser lệnh. Cấu trúc chính chỉ gồm:

- shared/skills/: các file SKILL.md.
- codex/AGENTS.md: rules dành cho Codex.
- claude/CLAUDE.md: rules dành cho Claude.
- install.sh: copy skills và chèn rules vào config.
- tests/install.sh: kiểm tra installer.

Trong codex/AGENTS.md, no comment hiện được kích hoạt khi dòng đầu tiên không rỗng chính xác là:

no comment

Nó chỉ có hiệu lực cho lượt hiện tại. Còn clear conversation và compact conversation hiện cũng chỉ là instruction trong AGENTS.md, nghĩa là agent phải đọc hiểu rồi tự thao tác file.

Skill shared/skills/compacting-conversations/SKILL.md có quy trình compact khá đầy đủ, nhưng đây là compact các file trong thư mục conversation/; nó không phải lệnh native để compact context của ứng dụng/model.

Vì vậy hiện tại:

- Gõ no comment: có, nhờ rule.
- Gõ clear conversation: có, nhưng agent phải tự hiểu và xử lý.
- Gõ compact conversation: có, qua skill xử lý file.
- Gõ $no-comment: chưa có.
- Gõ /clear hoặc /compact riêng của DotAgent: chưa có parser.
- Không gọi model, chạy lệnh ngay: chưa có.
- Autocomplete sau khi gõ /, $, @: chưa có.

Điểm mấu chốt: không thể tạo command native chỉ bằng AGENTS.md hoặc SKILL.md. Hai file này chỉ hướng dẫn model sau khi message đã được gửi. Muốn lệnh chạy ngay, cần thêm một lớp command parser vào chính ứng dụng/runtime nhận input.

Thiết kế phù hợp sẽ là:

input box
  -> command parser
  -> /...  : session command
  -> $...  : skill/profile
  -> @...  : file/folder reference
  -> #...  : mode/tag
  -> phần còn lại mới gửi cho model

Ví dụ:

/no-comment on
/clear
/compact
$room-builder
@Content/Props
#planning

Tôi khuyên dùng / cho toàn bộ command điều khiển:

/no-comment on
/no-comment off
/skill room-builder
/clear
/compact
/compact keep requirements and pending tasks

@ nên giữ riêng cho file/folder reference. # có thể dùng làm mode/tag, nhưng cần cẩn thận vì nó thường xuất hiện trong comment hoặc Markdown.

Cần thêm:

1. CommandRegistry: tên lệnh, alias, help, autocomplete, hàm thực thi.
2. CommandParser: nhận diện command trước khi gọi model.
3. SessionState: lưu skill đang bật/tắt và mode hiện tại.
4. SkillResolver: nạp nội dung SKILL.md vào context.
5. ConversationController: xử lý clear/compact trực tiếp.
6. Test cho parser, alias, command lạ và command có tham số.

Một giới hạn quan trọng: nếu G:\dotagents chỉ tiếp tục là bộ file cài cho Claude/Codex thì nó không thể tự tạo parser cho ô nhập của Claude/Codex. Khi đó cần sửa chính Dot client/runtime, tạo wrapper CLI đứng trước agent, hoặc dùng slash commands mà host đã hỗ trợ sẵn.

Nói ngắn gọn: bộ rules hiện tại đã mô tả đúng hành vi, nhưng chưa có cơ chế ký tự đặc biệt chạy tức thời. Muốn đạt đúng mục tiêu của bạn, cần xây thêm command layer ở runtime.
