# Preserving User Git Identity

## Overview

Commits represent the repository owner's Git identity. Keep that identity intact and keep generated work focused on its technical content, without automated-author attribution.

## Required checks

Run these checks before every commit and again before every push:

```bash
git config user.name
git config user.email
git diff --cached --check
git diff --cached
```

If `user.name` or `user.email` is empty or unavailable, stop before commit or push. Ask the user to configure or confirm the intended identity. Do not set it yourself.

## Identity rules

Never:

- Set or modify `user.name` or `user.email`, locally or globally.
- Use `git commit --author`, an alternate author environment variable, a bot account, or an automated-tool identity.
- Add a `Co-authored-by` trailer or other authorship trailer for an automated tool.
- Rewrite existing commits, change another person's attribution, or remove copyright, license, or provenance already present in the project unless the user explicitly requests it.

The current Git configuration is the only identity to use. A missing configuration is a stop condition, not permission to guess, impersonate, or substitute another identity.

## Attribution review

Review staged source, commit message, commit template, trailers, changelog entries, release notes, and PR text you create. Remove attribution that describes the producing tool rather than the technical work, including:

| Do not add or retain | Use instead when content is needed |
| --- | --- |
| Tool/model names or bot identities | Technical description of the change |
| `Generated by …` or `AI-assisted` | The behavior, constraint, or reason |
| Automated-tool co-author trailers | No trailer unless a real required trailer applies |
| "Written by" automated attribution | A normal technical comment, only if useful |

Do not delete existing attribution merely because it resembles one of these examples. Remove only text you introduced or text the user specifically asked to remove.

## Before pushing

1. Re-check the configured name and email.
2. Inspect the exact commits and metadata about to be pushed.
3. Confirm there is no automated-author attribution in newly created content.
4. Push only when the user has authorized the push.

## Common mistakes

| Rationalization | Required response |
| --- | --- |
| "The release is urgent." | Urgency does not permit identity substitution or attribution leakage. |
| "The Git identity is missing; I can fill it in." | Stop and ask the user to configure or confirm it. |
| "A co-author trailer is only metadata." | Metadata is still public attribution; omit it. |
| "Removing every attribution is safer." | Preserve existing copyright, license, and user-authored provenance. |

## Red flags — stop and review

- A commit command includes `--author` or author-related environment variables.
- Git reports an unknown, empty, or unintended identity.
- A generated comment, template, commit message, trailer, release note, or PR text names an automated tool.
- A push is requested before the staged diff and commit metadata were checked.
